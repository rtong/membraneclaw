# 可执行工程 Skill 最小原型规格 v0.1

日期：2026 年 9 月 6 日

用途：与导师讨论研究设计，并作为批准实施前的规格依据。

状态：方案草案；尚未实现执行器，未运行新实验。文中阈值和预算是待审核的试点建议，不是实验结果。

## 1 本次建议与决策边界

建议基本遵循老师 Figure 1 的路线：D1–D5 发展单模块工程技能，D6 检验组合式工具编排，D7 再检验现场知识、时间状态和人工把关。拟议方法不训练 9B 的权重，而是将强模型的可核查示范提炼为短小、可组合的工程 Skill，由固定程序执行关键约束，再根据开发反馈迭代 Skill。

通俗地说：5.6 协助编写和改进操作规程；9B 根据题目选用、填写和组合规程；程序负责记录输入、执行动作、检查引用和限制退出。程序不能保证模型理解正确，也不能保证每道题获得高分。

本轮只拟定规格，不改动源代码、实验配置、现有 Skill、原始题库、评分标准或冻结运行；不创建远端模型预设，不调用付费模型，不执行模拟器。后续实施和实验预算需另行确认。

### 1.1 要回答的三个问题

1. 教师的工程经验能否被提炼成短 Skill，并提高固定 9B 的解题质量？
2. 将相同的程序性要求落实为执行约束，能否减少参数漂移、结果错接和缺证据结论？
3. 在固定执行器和预算下，反馈驱动的 Skill 迭代能否继续提高表现，并迁移到未参与开发的新任务？

三者必须分别验证。执行器有效，不等于自进化有效；开发题涨分，不等于泛化有效；输出结构完整，不等于工程决策正确。

### 1.2 本版本的最小范围

- 覆盖一个单模块边界问题、一种串联任务和一种并联任务。
- 完整展示并联任务的示范提炼与执行设计；串联任务先处理已发现的输入口径疑点。
- 仅组合审核过的动作，不让进化器生成和运行任意代码。
- 第一阶段不加入在线 5.6 解题、模型型 Verifier、多智能体或跨题在线记忆。
- 新的 D1–D6 Skill 实验关闭外部事实 RAG；现有 RAG/Router 实验保留，不合并为新方法结果。

### 2.1 建议调整而非照搬的部分

1. **任务数**：原方案 118 题、D5 为 14 的口径应改成实际冻结数据数量。
2. **记忆**：D6 已需要单题工作状态；D7 再引入跨时间的现场状态，两者不混称。
3. **能力增长**：“Skill 越难越有效”“9B 接近 Teacher”是待检验假设，不预写成图注结论。
4. **安全成功**：同时报告质量分与安全约束下成功率。缺少必要验证应记为未证实，不能当成已安全。
5. **重复性**：老师建议的每题五次可以作为正式阶段目标；不能把现有单次记录写成已完成五次。重复运行按题聚类，而非当作新增题。
6. **Figure 3 统计**：D6a 仅七题，不预承诺含大量协变量的稳定混合效应模型；先做配对和拓扑分层描述。
7. **技能不匹配对照**：保持长度和接口兼容，不能故意强迫错误单位或危险动作；不兼容时记录拒绝，不靠人为制造失败证明优势。

## 3 现有项目可以复用什么

当前协议以 Tools、RAG 与 Router 为主；本方案是新的独立研究分支，并未修改该协议。历史 Solver Skill 的结果可用于开发诊断，但不与新条件合并为一个受控排行榜。

### 3.1 已核对的实现与证据

- `src/auto_evaluate/runner.py` 的 `_execute_work_item` 发起模型请求，再提取轨迹和检查完成状态；本地尚不是每次工具调用的逐步调度者。
- `src/auto_evaluate/openwebui.py` 使用 `/api/chat/completions` 接收远端响应与事件。这不自动提供“每次调用前拦截”的能力。
- `docs/EXPERIMENT_PROTOCOL.md` 已规定题目、参考答案和裁判的隔离边界，可作为新分支的基础。
- `docs/SKILLS_EVIDENCE_AUDIT.md` 将旧 Solver 结果定位为探索性证据；未发现完整、可确认的 Verifier Skill 定量实验，不把其他状态提示实验改名为 Verifier 实验。
- `context-reset-finalizer` 是既有无工具收尾路径，不等于补做缺失模拟；新分支不得把它当成工程验证器。

### 3.2 拟新增而非重写

| 拟议组件 | 职责 | 不承担的职责 |
|---|---|---|
| 任务输入接口 | 只交付问题正文、通用工具规范 | 不读取测试题答案、评分点或真实拓扑 |
| Skill 注册表 | 版本、适用条件、短说明、动作定义 | 不提供按题号查找的标准答案 |
| 计划接口 | 接收 9B 的短计划和输入提取结果 | 不让 5.6 现场代替 9B 写测试计划 |
| 固定解释器 | 执行已审核的动作类型与依赖规则 | 不执行任意新 Python、不学习修改评分器 |
| 任务状态库 | 输入快照、候选、结果、引用、预算 | 不跨测试题传播标准答案和评分反馈 |
| 工具适配器 | 参数映射、单位转换、原始结果保存 | 不偷偷修正模型的工程决策 |
| 离线候选比较器 | 根据开发结果选择 Skill 版本 | 不读取最终测试集来晋升版本 |

这些名称是设计概念，不代表对应模块已存在。优先新增独立执行入口，通过现有记录格式接回评分和报告，避免直接改写现有远端执行路线。

## 4 三类开发题及选择依据

选题依据是覆盖失效机制和依赖结构，不是挑选新版 Skill 的高分样本。以下全部标记为开发题，可看参考答案并迭代；不作为未见测试。

| 开发代号 | 真实题号 | 结构与重点 | 当前使用状态 |
|---|---|---|---|
| P1 | `D1-1a-feasibility` | 单工具、多工况、双边界、无共同可行区间 | 可做流程开发；全域无解主张仍需明确范围与单调性依据 |
| P2 | `D6-6b-n01-minimum-area-calcium-softening` | RO 实际回收率 → 水化学；残余 Ca 与去除量区分 | 先做接口与假设审计；暂不以参考化学数值作严格验收 |
| P3 | `D6-6c-01` | RO 与系统模型并联，按候选汇合后排名 | 完整示例首选；默认参数需在实施前显式登记 |

| 题目 | Baseline | Tools | 5.6 加 Tools |
|---|---:|---:|---:|
| P1 | 19 | 61 | 97 |
| P2 | 21 | 60 | 88 |
| P3 | 29 | 55 | 100 |

来源为同一冻结 run 的 `ratings.jsonl` 与 `judge_mapping.json` 联接。分数是原裁判记录，本轮未重新评分，不能据此认定教师示范没有错误。

### 4.1 P1 验证什么

题目固定压力 51 bar、膜参数和三个进水工况，只允许改变膜面积。必须同时满足产水量、回收率、通量、截盐率和产水盐度。

历史参考与教师给出的关键证据为：工况 B 的产水边界在 354/355 m²，盐度边界在 308/309 m²。Tools 的历史诊断指出，它转去追踪工况 A 的近似区间，随后上下文不足，最终缺少支撑无解的关键边界。

可提炼的技能：先同点筛查工况，再选择当前最有信息的边界；分别保存产量与水质证据；不把“面积越大”视为全面改善。

不能写入 Skill 的内容：工况 B 固定最差、308/355 是通用边界、所有此类题都无解。

无解证书还需标注适用域。少数相邻点只能直接证明局部转换，不能无条件证明全部正面积上不存在其他可行区间。实施前需确认题目的有效搜索域，以及可用的单调性依据或完整离散域；不充分时保留“在已验证范围内”的限定。

### 4.2 P2 的关键发现和处理

题目规定面积候选 45/50/55/60 m²；Ca 候选是残余流量 0.025/0.020/0.015/0.010 mol/s；每去除 1 mol Ca 增加 2 mol Na；水化学必须使用对应 RO 候选的实际回收率。

这里的串联边传递的是**实际回收率**，加上题面给定的离子组成，不是从 NaCl 简化 RO 模型中凭空提取完整离子浓水组成。不得将原水先手工浓缩后又传入回收率，造成重复浓缩。

现有 5.6 记录 `teacher-tools::D6-6b-n01-minimum-area-calcium-softening` 显示：

- 实际使用 `water_recovery = 0.4254858648822814`，对应 55 m² 的 RO 输出。
- 化学调用未显式给出进水 `ph`，返回输入采用 7.0。
- 请求的矿物只有 Calcite、Gypsum。
- 参考答案列出 Calcite、Gypsum、Anhydrite、Dolomite 四种矿物。
- 40% 去除点，教师的 Gypsum SI 约 −0.107260、pH 约 6.930266；参考约 −0.072806、6.433555。推荐相同，数值口径不同。

本轮不能确定参考答案究竟使用了什么进水 pH，不能根据结果反推一个值并宣称已核实。进水 pH 与出水 pH 下限是两个不同量，也不能把 6.30 当成进水 pH。

**处理决定**：保留该题用于回收率引用、候选语义、化学计量与错误拦截测试；暂缓严格的端到端化学正确性验收。需题目作者明确矿物集合与缺省参数政策。澄清作为版本化补充，对所有新条件一致开放；不得暗改冻结原题或历史评分。若无法澄清，在查看原型得分前选择另一道信息完整的串联开发题并记录原因。

### 4.3 P3 为什么适合作为完整示例

题面明确要求两个工具分支独立运行，按候选 ID 汇合。历史 Tools 的主要错误不是“不知道要算能耗”，而是系统分支漏传候选压力，导致采用 70 bar 默认值，最终错误排除方案。

这是适合受控执行的具体问题：同一个候选中的压力必须映射到两个工具各自的参数名，不能只在 RO 分支正确、系统分支遗漏。

P3 的公开题目已经明确给出并联关系、工具名和联接要求。因此它能检验“按已知要求正确执行”，不能单独证明 9B 自主发现了任务拓扑。独立测试需区分说明充分的任务和需要模型自行分解的任务；不删除原题提示后仍沿用原题身份和原难度。任何去提示视图都应单独版本化，并先确认信息仍足以解题。

## 5 完整样例 从教师示范到受控执行

本节分清三种材料：教师实际记录、由其提炼的通用技能、拟议的 9B 输出和程序行为。后两种不是本轮真实模型运行。

### 5.1 题目和公开约束

P3 比较四个方案。膜单元进水为 1 kg/s；系统进水为 0.10 m³/s；系统膜面积为对应单元面积的 100 倍。两个工具不是彼此上下游。

| 候选 | 压力 bar | 单元面积 m² | 系统面积 m² | PX 效率 |
|---|---:|---:|---:|---:|
| A | 58 | 70 | 7000 | 0.95 |
| B | 62 | 60 | 6000 | 0.95 |
| C | 65 | 55 | 5500 | 0.95 |
| D | 62 | 60 | 6000 | 0.90 |

各方案均为 25 °C，A_comp = 4.2e−12，B_comp = 3.5e−08。须同时满足：膜产水 ≥0.370 kg/s、产水盐度 ≤350 mg/L、入口 CP ≤1.30、系统产水 ≥0.041 m³/s、SEC ≤2.75 kWh/m³，然后在可行方案中选 SEC 最低者。

题目还要求每候选两个分支各运行一次，输出通量、回收率、LCOW、CAPEX 等信息。不能因某方案已违反一项约束，就跳过题目明确要求的其他输出。缺少年度权重，不计算年度加权指标。

### 5.2 教师实际做了什么

来源：`teacher_responses.jsonl`，记录键 `teacher-tools::D6-6c-01`。

| 事件 | 实际动作 | 可提炼的经验 |
|---|---|---|
| T001 | `watertap.describe_ro_parameters` | 先确认工具职责与参数，不从字段名称猜口径 |
| T002–T005 | 四个候选各调用一次 `simulate_ro` | 单元面积、压力、温度与膜参数按同一行输入 |
| T006–T009 | 四个候选各调用一次 `simulate_swro_system` | 使用系统面积与系统进水，压力映射到 `p1_pressure_bar` |
| 最终回答 | 联接分支、检查五项约束、排序与解释 | 先判断可行，再比较目标；能耗来自系统工具 |

实际记录为 8 次模拟和 1 次描述调用，不是“8 次全部工具调用”。分支独立不代表历史调用在墙钟时间上并发执行；本原型也先用串行调度保证可审计。

教师声明保留未给定的工具默认值，包括 RO 盐度 0.035 质量分数、系统 TDS 35.0 g/L、泵效率等。这些默认值要由工具版本和公开接口规范确认并登记，对全部新实验条件一致提供，不能藏在候选 Skill 中。盐度 ppm 与 mg/L 的转换也应保留口径依据，不能无条件改名。

### 5.3 提炼出的短 Skill 样本

以下为拟议说明文本，不是已部署的 `SKILL.md`。其中没有 P3 的答案、候选名和具体阈值。

> 适用于有限候选的多模型独立分支比较。先从问题提取候选表、每个工具的计算尺度、全部约束与排序目标。两个分支各使用同一候选行的参数，不把一个分支的输出输入另一分支。对不同工具显式映射同一物理量的参数名，区分单元面积与系统面积。每条结果必须关联候选、场景、工具版本和输入快照。完成问题明确要求的分支与输出后，按候选联接，逐项检查约束，仅在全部通过的候选中排序。必要结果缺失时报告未证实，不用估算补成完成；解释至少两个未选方案，并说明默认值和模型边界。

该段应由 9B 的实际 tokenizer 测量长度。不得为了满足字数删掉适用条件、结果引用或退出限制。

### 5.4 拟议的 9B 短计划

下面是根据公开题目编制的目标格式示例，不是 9B 已经成功生成的计划。`question.*`、`nodes.*` 是拟议引用语法，不是现有接口。

```yaml
skill: parallel_candidate_join@0.1
goal: minimize_SEC_among_jointly_feasible
candidate_ref: question.candidates
constraint_ref: question.constraints
nodes:
  - id: membrane
    foreach: question.candidates
    action: call_ro
    input_profile: question.module_inputs
  - id: plant
    foreach: question.candidates
    action: call_swro_system
    input_profile: question.plant_inputs
  - id: join
    action: join_evidence
    needs: [membrane, plant]
    key: [candidate_id, scenario_id]
  - id: check
    action: check_constraints
    needs: [join]
  - id: select
    action: rank_feasible
    needs: [check]
    objective_ref: question.objective
  - id: report
    action: report_evidence
    needs: [select]
```

计划之外，9B 还须从正文提取输入、约束、输出要求，并保留其在原文中的出处。程序不是从 Gold_Answer 填充 `question.constraints`。人工标注的正确计划只能用于开发审核或明确标注的上界诊断，不能放进正式测试入口。

### 5.5 固定解释器如何执行

以候选 A 为例，程序读取已确认的候选行，通过公开接口映射：

| 物理量 | RO 参数 | 系统参数 | 检查 |
|---|---|---|---|
| 压力 58 bar | `feed_pressure_bar` | `p1_pressure_bar` | 两分支均显式传入，不能遗漏而采用默认值 |
| 单元面积 70 m² | `membrane_area_m2` | 不使用 | 不能给系统模型传 70 |
| 系统面积 7000 m² | 不使用 | `ro_area_m2` | 不能替换为单元面积 |
| 进水 | `feed_flow_mass_kg_s = 1` | `feed_flow_m3_s = 0.1` | 是两个明确给定的尺度，不直接互换单位 |
| PX | 不送入单元工具 | `erd_type`、`pxr_efficiency` | 不让 PX 效率直接改变单元膜结果 |

解释器只允许注册动作，如调用工具、转换单位、读取已有结果、联接、比较和报告。工作流本身可以声明任务相关先后与搜索策略，但不得修改工具规范、评分器或保护规则。

每次调用保存原始输入、补齐的默认值、输入哈希、原始输出、错误、求解状态、工具版本和结果编号。元数据中的版本不能伪装成工具已返回的求解收敛证据；返回结果缺少收敛字段时记录“未提供”，采用预先规定的输出校验，不自行补写“收敛”。

候选 ID 由调度器绑定到输入记录，不采用模型在自由文本中声称的归属。按候选和场景联接时，还要核对各分支适用的参数快照；不是要求不同工具的输入哈希彼此相等。

若 9B 合法修改计划或候选，生成新修订号；依赖旧输入的下游结果标为失效。重新规划不能继续引用旧工况的成功记录。旧记录保留以便审计，但不得满足新方案的完成条件。

## 6 9B 与程序各自负责什么

### 6.1 9B 的职责

- 理解公开问题，提取目标、变量、约束、候选、场景、输出要求和缺失信息。
- 从通用技能描述选择合适技能；不通过隐藏题族标签得到正确路线。
- 形成短计划，在搜索任务中根据当前观测提出下一候选或合理改计划。
- 对结果作简洁解释，明确模型边界。

### 6.2 程序的职责

- 验证语法、类型、范围、引用存在性及允许的动作。
- 依照已接受的任务输入锁定非决策字段，记录所有默认值和来源。
- 依照所选工作流检查前置条件、映射参数、保存原始结果、维护预算。
- 用确定性的比较逻辑生成约束状态和证据引用；不依赖“模型说 PASS”。
- 将报告声明与证据对应。缺证据时不得给出“已验证完成”的机器状态。

### 6.3 不能由硬控制消除的错误

9B 若一开始把任务目标、残余 Ca 或阈值理解错，格式校验仍可能通过。因此要单独评价提取准确率和计划正确率，不能只看执行成功。工具模型适用性、遗漏的现场约束和数值误差也不由程序执行保证。

通用算术与物理约束检查必须说明来源：题目中明确给出的要求、公开工具契约或事先审核的工程规则。不能直接读取测试 rubric 来决定需要计算哪些边界。

## 7 状态和上下文预算

### 7.1 单题状态的最小字段

```text
任务记录
  输入快照与原文出处
  已提取目标 变量 约束 输出要求
  技能版本与解释器版本
  候选与场景表
  计划节点及依赖
  工具记录 输入哈希 原始输出 证据编号
  约束状态与失败原因
  未完成节点 当前预算 终止原因
```

每题隔离。完整历史在外部保存，下一次模型调用只带公开问题的必要信息、当前技能、当前状态和当前动作所需结果。不能把所有原始 JSON 都压成一个不可检索的短总结；需有按字段访问原始记录的能力。

### 7.2 试点建议预算

具体值须经接口和 tokenizer 预检后，对所有候选条件一起冻结。以下不是对现有 2048 输出限制的静默修改，也不能与旧运行直接比较绝对分数。

| 项目 | 初始建议 | 约束 |
|---|---|---|
| 常驻说明 | 300–500 tokens | 不含当前题目与工具定义 |
| 单个激活 Skill | 300–600 tokens | 按需加载，常驻不超过两个 |
| 初始计划输出 | 目标 300–500 tokens | 给结构化提取留出单独预算，不能只靠截断 |
| 单次请求总输入 | 初始目标不超过 12k tokens | 含提示、工具 schema、引用结果和历史；以实际 9B 上限复核 |
| 单次最大输出 | 初始上限 2048 tokens | 给当前操作明确短目标；所有组相同 |
| 单题全部模型输出 | 初始总上限 12k tokens | 规划、修正、解释与最终报告全部计入 |
| 单题模型请求 | 初始最多 24 次 | 失败与修正均计数 |
| 单题模拟调用 | 初始最多 24 次 | 不是要求调用 24 次；失败、重试也计数 |
| 元数据描述调用 | 初始最多 4 次 | 与模拟次数分开统计，但都计成本和时延 |
| 单步修正 | 最多 2 次 | 仍受单题总预算限制 |

若某类任务公开要求的最小工作量已超预算，应在看候选分数之前统一调整该类预算，或声明任务不在原型覆盖范围；不能只给新 Skill 增加额度。不得一刀切继承旧版“六次工具调用”限制。

`completed`、`insufficient_evidence`、`infeasible_supported`、`invalid_plan`、`tool_failure`、`budget_exhausted` 分别记录。一次合法无解结论可以完成任务；预算耗尽不能自动转成无解。允许输出已完成部分，但保留失败状态。

新分支默认不调用旧无工具 Finalizer 来改变完成状态。如需要统一的收尾调用，应对全部新条件相同开放、计入预算，并且不能补做模拟或把未验证结论标成通过。

## 8 公平对照与最小实验

原先提出的三组可以验证方向，但不足以完全区分“程序约束”与“技能知识”的作用。本规格建议用四组的二乘二设计，补足无 Skill 的硬执行对照。

### 8.1 四组共用条件

同一 9B 权重与服务设置、公开问题、工具版本、工具默认值、基础状态存储、逐步接口、结果展示、总预算、采样参数、评分器及恢复政策。均关闭外部事实 RAG。所有组均必须输出可解析的动作；通用接口和环境保护不能关闭。

“软”不是不记录和不检查，而是不以任务相关的程序性前置条件阻止动作；使用同一套旁路检查记录违规，再由固定裁判评价。“硬”才以已接受计划和任务合同控制执行。测试仅调用模拟器，不进行现场设备操作。

| 条件 | 匹配工程 Skill | 任务相关语义执行约束 | 用途 |
|---|---|---|---|
| C00 | 无；只有最小通用接口说明 | 旁路记录，不强制匹配流程 | 新执行底座基线 |
| C10 | 有，初始短 Skill | 旁路记录 | 测量文字程序知识 |
| C01 | 无匹配 Skill；由 9B 自拟计划 | 强制检查自拟计划及公开输入合同 | 测量通用受控执行 |
| C11 | 有，与 C10 相同语义内容的 Skill | 强制执行该技能实例化计划 | 初始完整方法 |

C01 不能偷偷拿到教师的任务流程；C00/C01 不能拿到隐藏题族路由。四组都要自己提取问题，人工正确计划只用于单独标注的诊断实验。

重点比较：C10−C00 为软 Skill 作用；C01−C00 为通用执行控制作用；C11−C01 为相同硬底座上的匹配 Skill 作用；C11−C10 为有 Skill 时的执行控制作用。交互项可描述，但小样本不作强统计结论。

旧 Tools 结果仅提供开发背景。若要估计新执行底座相对旧 OpenWebUI 完整循环的影响，另加桥接条件，按同一时间与设置重新运行；不能用跨版本差异冒充 Skill 增益。

### 8.2 分阶段规模

1. **无模型验收**：执行第 5.7 节及串联单位/引用测试，检查程序能否按规格接受和拒绝动作。
2. **接口烟测**：在另行批准后，每个必要接口做最少量调用；确认相同 9B、工具、输出和日志可用。烟测不是质量实验。
3. **开发试点**：三题 × 四条件 × 三次独立生成，共 36 个解题 episode。每个 episode 包含多次模型和工具调用，不能把 36 写成 36 次 API 请求。
4. 若 P2 尚未澄清，先进行 P1/P3 的 24 个 episode，P2 只做不依赖化学真值的结构测试；记录完整三题试点未完成。
5. 完成后再决定是否扩展任务与启动离线进化；不一开始就跑 117 题所有条件。

这些数目是拟议上限，不是本轮执行授权。预算清单应另列规划调用、动作调用、修正、裁判、教师与模拟器成本。

### 8.3 评价指标

主要指标是原有 100 分任务质量；保留失败和不完整输出的实际部分得分，不能只看成功样本。运行有效但模型失败不能被完整性开关从分母删除。纯基础设施事故按预注册规则重试或成组重跑，并保留原记录。

辅助指标：逐题分数、约束违规、证据闭合、输入提取正确率、计划有效率、参数漂移、错接引用、原生完成、受控修正、上下文失败、冗余调用、全部 tokens、时延。工具效率仍单独报告，不混入任务质量。

另定义“安全约束下成功”：满足预注册的任务完成标准、必要证据齐全且无已定义硬约束违规。软件运行成功不等于该指标；未证实不等于安全。

三题三次只是开发信号，不适合声称显著泛化。先报告每题三次均值、范围和配对差值；扩大后按任务聚类计算区间，不能将同题重复当独立题。Judge 使用匿名响应与轨迹，不告知 Skill 版本；分歧案例由专家复核，抽样规则在看效果前确定。

运行顺序按题和重复轮次交错或随机化，避免所有新方法集中在不同服务负载时段。缓存规则、并发度和模型采样种子政策一致。选定版本后用新独立生成作确认，不把用于挑选版本的最佳一次结果当作复验。

## 9 离线自进化的操作定义

本规格称为“教师辅助、反馈驱动的技能进化”，不称为 9B 权重强化学习。若每轮由人决定修改，报告为人参与迭代；只有候选生成、验证和晋升规则自动执行后，才描述对应自动化程度。

### 9.1 可更新与不可更新

| 可更新 | 必须固定 |
|---|---|
| Skill 短说明、适用条件 | 测试集、测试答案和评分标准 |
| 注册动作之间的工作流组合 | 工具物理实现、通用保护与适配器契约 |
| 搜索次序与明确适用的停止策略 | 实验总预算与对照组设置 |
| 所需结果字段和局部状态表达 | 输入出处与证据防伪要求 |

技能可声明更具体的前置条件，但不能降低通用硬规则、删掉题目约束或允许无证据通过。新增工程检查须有可审查来源，不能由测试评分点反推后私下加入。

### 9.2 拟议进化步骤

1. 从已审核的开发示范提炼种子版本；P2 有争议的数值不进入种子。
2. 让固定 9B 在开发集运行；保存完整轨迹与失分定位。
3. 给 5.6 一个短失败包：相关问题、当前技能、首个可观察错误、必要输入输出、开发评分反馈。无必要不发送整份长轨迹。
4. 要求生成最多两个局部候选，说明修改目标和可能退化的任务；不得生成题号匹配与特定最优值。
5. 校验格式、长度、禁改字段和无泄漏要求，再在训练开发样本运行。
6. 在开发验证子集上与现任版本配对比较；验证子集不是最终测试集，反复选择也会过拟合。
7. 达到预定晋升门槛才接受；否则保留旧版。保存全部失败候选，不只展示最佳版本曲线。

### 9.3 试点晋升与停止建议

在执行器冻结后，初始最多三轮、每轮最多两个候选。建议使用预先划定且不只含三道种子题的开发验证集；规模未确定前不运行自动晋升。

拟议继续门槛：平均任务质量至少提高 5 分，至少两个任务结构类别有改善，无新增已定义硬约束违规，单题均值不下降超过 10 分，全部成本/时延不突破预定容忍线。这里的 5/10 分是项目决策阈值，不是统计显著性，也不是保证有效；须在看新结果前审核冻结。

资源容忍线建议先设为：每题平均全部模型 token 成本不超过现任的 1.25 倍，中位墙钟时延不超过 1.5 倍，并始终满足第 7 节绝对预算。缺少价格时报告 tokens、模拟次数和时延，不编造美元成本。对照成本为零或计量缺失时不计算比例，先补齐计量。离线教师与搜索成本单列，再说明按多少次部署摊销，不能直接从单题成本中消失。

若质量相当而成本更低，保留为效率候选，不写成能力增长。若程序控制有效但进化无额外收益，缩小主张为执行方法；若两轮修改只改善格式、没有改善工程质量，则暂停扩大运行，回查输入、工具可观测性和预算，不继续无限追加提示。

进化阶段需另列候选生成、开发运行、验证和裁判预算。正式测试只使用最后冻结的 Skill，5.6 不为当前测试题生成计划或修补方案。

## 10 新测试题与信息隔离

当前 D1–D6 已经被多轮查看和开发使用，可用于发展方法和回归，不能通过重新划分文件夹恢复成完全未见测试。

建议在方法和验收口径冻结后，由未参与本轮修改的出题者提供新任务。至少变化约束组合、控制变量或串并联依赖中的一类；单纯改数字的近重复题只支持有限鲁棒性检查。新的 D6 组合任务与 D7 的现场有效性分开报告。

| 信息 | 开发与提炼 | 正式在线解题 | 最终裁判 |
|---|---|---|---|
| 公开问题与通用工具说明 | 可用 | 可用 | 可用 |
| 开发题答案及评分诊断 | 可用，必须标开发 | 不作为当前题外挂答案 | 可用 |
| 测试答案、隐藏 rubric、真实拓扑 | 禁止用于候选修改 | 禁止 | 可用 |
| 9B 当前题真实工具结果 | 可用 | 可用 | 可用 |
| 测试后得分和专家意见 | 冻结前不可见 | 不回流本轮解题和其他测试题 | 用于评价 |

任务运行器与裁判使用不同输入对象；“代码没有主动读答案”不足以隔离，应由数据接口不交付答案。运行器不能根据完整题库路径和题号加载匹配策略。D1/D6 标签与隐藏难度只用于事后分组。

## 11 技术预检与实施顺序

### 11.1 必须先确认的接口条件

1. 同一 9B 是否支持独立的短计划和动作请求，且不会在服务端隐藏启动另一套自动工具循环？
2. 是否能通过现有服务直接调用同一工具、记录完整参数与原始结果，并获得版本或部署标识？
3. 是否能使用匹配 tokenizer 统计包含工具定义的完整请求长度？
4. 默认值、失败返回和精度能否显式记录？流式摘要中被截断的信息能否保存在原始事件中？
5. 新路线的工具绑定和模型权重是否与对照一致？界面模型名相同不是充分证明。

本轮只检查了本地代码，未探测远端端点，所以上述均为待验证项。若没有逐步调用能力，则不能用前置规划提示冒充硬控制；可讨论新增本地调度入口或服务端拦截接口。不得未经同事同意改写共享服务。

### 11.2 建议里程碑

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| M0 规格讨论 | 本文、P2 疑点及选题说明 | 导师认可问题、范围、Skill 定义与测试隔离 |
| M1 接口预检 | 模型/工具契约、版本、默认值、请求预算 | 能真实逐步调用并完整留痕；共享环境变更获授权 |
| M2 最小执行器 | 计划、状态、工具适配、日志与错误测试 | 必须拦截的测试全部通过，合法路径不被错误拒绝 |
| M3 受控开发试点 | 四组逐题结果、失败、成本与轨迹 | 初步质量或证据收益，且未靠泄漏、预算差异取得 |
| M4 离线技能进化 | 候选版本、修改原因、晋升与回退记录 | 固定执行器上观察到可复验的额外收益 |

M2 的语法/接口测试不需要裁判模型。M3 不直接推广到全部 117 题。每阶段新增独立配置与运行目录，不覆盖冻结 run，不恢复或删除历史 Verifier 派生文件。

## 12 拟议论文叙事与失败后的处理

可作为研究问题的表述：强模型的工程经验能否被压缩为可组合、可执行、可迭代的技能，使固定小模型在有限上下文内更可靠地完成多模拟器任务？

Figure 1 说明系统与发展路径；Figure 2 检验工具、匹配技能、执行方式与进化的贡献；Figure 3 用 D6 的参数映射、依赖传递、错误传播和成本解释增益。自进化版本曲线可以作为 Figure 2 的附加面板或补图，不能取代独立测试。

若进化无效：保留负结果，停止使用“进化提高能力”的结论。若只有强制检查有效：突出可审计执行，而非小模型学会了教师思维。若只有旧题有效：报告开发集适配，不能称为可泛化技能。若物理假设仍不明确：先澄清任务，不通过调提示去迎合参考数字。

## 附录 A 通俗术语

| 名词 | 本项目中的含义 |
|---|---|
| Skill | 可复用的工程操作规程，不是某题答案 |
| 声明式工作流 | 写清要做的动作与依赖，由固定程序解释执行 |
| 执行合同 | 输入、前置条件、输出和完成要求的明确约定 |
| DAG | 带方向且无循环的步骤依赖图；搜索循环另用有预算的迭代动作表示 |
| 状态 | 当前题已知条件、已算结果和剩余工作 |
| 证据编号 | 指向真实工具记录的索引，不是模型自由编造的引用 |
| 蒸馏 | 本文仅指把示范提炼成技能文本/流程，不更新 9B 权重 |
| 消融 | 有控制地移除一个组成部分，观察它的实际贡献 |
| 晋升 | 候选达到预定条件后替代现任版本 |
| 泛化 | 在未参与示范提炼与调参的新任务上仍有效 |
