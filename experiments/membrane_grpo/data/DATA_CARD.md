# Data card — membrane_grpo

## What this is

850 synthetic reverse-osmosis operating records, each paired with a structured
diagnosis. Generated by `task/generate.py` from a hand-written decision table;
**no plant data, no WaterTAP output, no measurements of any kind**. Every range,
threshold and probability is a teaching parameter chosen to make a reinforcement
learning experiment legible, in the same spirit as `experiments/toy_mdp`.

Do not use this to make decisions about a real membrane train.

## Provenance

| | |
| --- | --- |
| Generator | `task/generate.py`, seed `20260816` |
| Answer key | `task/decision_table.py` — 17 symptom combinations, 7 causes |
| Prompt | `task/prompt.py`, `PROMPT_VERSION = v1` |
| Integrity | `data/SHA256SUMS`, verified by `test_data_files.py` |

Regenerating with the same seed reproduces the files byte for byte. If you
regenerate, the checksums change and `test_checksums_match_the_files_on_disk`
fails until `SHA256SUMS` is rewritten — which is the point: a frozen split that
can be silently replaced is not frozen.

## Splits

| File | n | Purpose |
| --- | --- | --- |
| `train.jsonl` | 400 | GRPO rollouts |
| `dev.jsonl` | 200 | every tuning decision, every go/no-go |
| `test.jsonl` | 200 | **untouched until the final evaluation** |
| `holdout_shift.jsonl` | 50 | two distribution-shift slices, 25 each |

Root causes are balanced to within one case per split, so a constant guesser
scores 1/7 = 14.3% on `root_cause`. Splits are disjoint at the level of the
whole record, checked by `test_no_record_leaks_between_splits`.

### The two shift slices

* `shift_temp` — feed temperature drawn from 10–15 °C or 28–33 °C, against
  20–25 °C in training, and `hard` tier only. The correction factor is therefore
  much further from 1 than anything seen during training.
* `shift_boundary` — sampled 0.6 pp from the flag thresholds instead of 2.0 pp.
  The arithmetic is ordinary; what is hard is that a small error in it now
  changes the label.

Both exist to separate "reward went up" from "the model got better", so they are
never trained on.

## Difficulty tiers

`easy` (≈63%) and `hard` (≈37%) differ in exactly one thing: whether the two
feed temperatures are equal. When they are, `TCF` cancels and the first
computation is a plain percent change. When they are not, the model has to
evaluate `1.03 ** (25 - T)` twice. The prompt wording is byte-identical between
tiers, so tier is a clean arithmetic-difficulty variable rather than a confound
with format. `test_hard_tier_actually_needs_the_correction` checks that skipping
the correction gets a hard case wrong by more than the reward's 0.5 pp tolerance.

## How a case is built

Backwards, because forward sampling produces mostly uncoverable symptom
combinations and a badly skewed label distribution:

1. pick a root cause, then one of its symptom combinations from the table;
2. sample three percent changes, each at least `margin_pp` from every threshold;
3. sample the t0 readings and solve for the t1 readings that produce those changes;
4. round every reading to instrument precision;
5. **recompute the answer from the rounded record** and discard the case if it no
   longer implies the intended label.

Step 5 is what makes the shipped answer trustworthy: it is not the label the
case was built from, it is the label the case's own numbers produce.
`test_every_shipped_answer_is_derivable_from_its_record` re-runs it on all 850.

## Known simplifications

These are wrong-but-useful, and they are why this is not a diagnostic tool:

* **Organic fouling and compaction** are separated here by whether salt passage
  falls or holds. In practice the two overlap heavily and are distinguished by
  history and autopsy, not by a single reading pair.
* **Compaction is reported at one stage.** Real compaction is distributed; the
  record names the stage where it is most pronounced.
* **One cause at a time.** Real trains foul in combination, and the table has no
  entry for that.
* **The anomaly's stage is given, not inferred.** It appears in the prompt, so
  the `stage` field is a copy rather than a deduction. This is deliberate — it
  is a component that should saturate early, and watching it saturate is part of
  the experiment.
* **Feed pressure and recovery are distractors.** Both appear in the record and
  neither is needed. Feed pressure is held fixed between readings.
* **No noise.** Every record is exactly consistent with its label. A real
  normalization carries instrument error that would make some cases genuinely
  ambiguous.

## Fields

```
id       string     "<split>-<slice>-<index>"
split    string     train | dev | test | holdout_shift
slice    string     main | shift_temp | shift_boundary
tier     string     easy | hard
record   object     t0, t1 (seven readings each), recovery_pct, anomaly_stage
answer   object     the graded schema — three numbers, three flags, stage,
                    root_cause, action
meta     object     generator bookkeeping: intended_cause, intended_key,
                    severe, margin_pp. Never shown to the model and never graded.
```
